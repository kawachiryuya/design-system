## 概要

Application shell の骨格を提供する composite。**mobile と PC で構造そのものが変わる** タイプの layout で:
- **mobile (< lg)**: Header (top) + subBar? + main + footer? + BottomNav (bottom fixed)
- **PC (>= lg)**: Sidebar (left fixed) + 右 pane (subBar? + main + footer?)

Header / Sidebar / BottomNav / subBar / footer の **中身** は consumer 提供 (slot)。AppShell は配置・breakpoint 制御 (`lg:hidden` / `hidden lg:block`) と内側 main の `max-w` / `px-container` / `py`、footer landmark の配置を担当する。`PageTitleProvider` 等の context は **consumer 側で実装**、AppShell は router/state 依存を持ち込まない。

## 5 slot の役割

| Slot | 表示条件 | 想定中身 | DOM 配置 |
|------|---------|---------|---------|
| `header` | mobile のみ (`lg:hidden`) | ブランドロゴ / ハンバーガー / 戻る button | 最上部、`flex` の最初の child |
| `sidebar` | PC のみ (`hidden lg:block`) | ナビゲーション menu / ロゴ / utility link | 左、`<aside>` でラップ |
| `bottomNav` | mobile のみ (`lg:hidden`)、かつ `showBottomNav=true` | tab bar (3-5 個の primary destination) | 最下部 (consumer 内部で `fixed bottom-0` 想定) |
| `subBar` | 両方 (consumer 内部で表示制御推奨) | breadcrumb / step indicator / page title | main の上 |
| `footer` | 両方 | サービス / サポートリンク + 著作権など全ページ共通フッター | 内容カラム最下部 (`main` の後)、AppShell が `<footer>` でラップ |

すべて optional。omit すると AppShell はその slot を描画しない。

**footer は「内容カラム幅の帯」**: レールの下までは貫かず、レール幅ぶんオフセットした内容カラム全幅の帯として描画される。本文 (`main`) が `flex-1`・footer が `shrink-0` なので、**短いページでもフッターはビューポート底に来る** (中央に浮かない)。帯の内側読み幅は consumer が `<Section>` / `<Center>` で絞る (`contained` / `full` の 2 層モデルと一貫)。AppShell が `<footer>` landmark を提供するため、consumer は中身を二重に `<footer>` で包まない。

## Breakpoint 挙動

| viewport | 配置 |
|----------|------|
| **`< shell` (mobile/tablet)** | 縦積み: header / subBar / main / bottomNav |
| **`>= shell` (PC)** | 横並び: sidebar (left) + (subBar + main 縦並び) |

切替点は **semantic breakpoint `shell:`** (既定 = lg / 1024px)。breakpoint トークンから派生し、consumer は自前 preset で `screens.shell` を override 可能。列レイアウトの `cols:` (TwoColumn 等) とは別軸なので、shell 切替と列切替を独立に調整できる。

**bottomNav 表示時のクリアランス**:
- mobile: `pb-20` (= h-16 nav + 16px gap)
- PC: `pb-8` (= 32px、token desktop padding)
- `showBottomNav={false}` だと両方とも `py-container` (= token-driven 対称 padding)
- **footer がある場合**、内容カラム最下部の要素は footer になるので、mobile のクリアランスは main から footer へ移る (footer に `mb-20`、main は通常 padding に戻る)。これで footer も固定 BottomNav に隠れない。

## consumer 側の責務

### 1. slot コンポーネント本体の実装

`<Header />` / `<Sidebar />` / `<BottomNav />` / `<PageSubBar />` の **中身** は consumer が決める。ブランド / メニュー構造 / アイコン選定は product 固有なので DS に持ち込まない。

```tsx
// 標準的な利用例
import { Header, TopHeader, BottomNav, PageSubBar } from './layouts';

<AppShell
  header={<Header />}
  sidebar={<TopHeader />}
  bottomNav={<BottomNav />}
  subBar={<PageSubBar title="ホーム" />}
>
  <Outlet />
</AppShell>
```

### 2. PageTitleProvider 等の Context

各 route の meta (title / breadcrumb / step / showBottomNav) を画面間で共有したい場合、**consumer 側で Context** を持つ。

```tsx
// consumer 側
<PageTitleProvider>
  <Routes>
    <Route element={<AppShellWrapper />}>{/* AppShell + Outlet を wrap */}
      <Route path="/" element={<HomePage />} />
      ...
```

AppShell は受け取った props をそのまま render するだけ、router 依存ゼロ。

### 3. BottomNav の fixed positioning

`BottomNav` slot の中身は `fixed bottom-0` を **consumer 側で適用**。AppShell はクリアランス (mobile main `pb-20`) のみ担当する。

```tsx
const BottomNav = () => (
  <nav className="fixed bottom-0 left-0 right-0 z-40 ...">
    {/* ... */}
  </nav>
);
```

### 4. content 制約の 2 層 (`contentMax` = 枠 / Center = 読み列) と `layout`

AppShell が効かせるのは **shell フレーム幅** (`contentMax`、既定 1280px の cap) であって読み列ではない。
本文の読み列は内側で `<Center>` を入れ子にして絞る — **「AppShell > Center」が本文系の推奨パターン**。
`contentMax` の cap は **backstop** (= `<Center>` 忘れでも全画面には暴走しない安全網) であって、
Center の代わりではない。

```tsx
// contained (既定・安全)。本文は中で Center を足す
<AppShell contentMax="default"> {/* shell フレーム = 1280px cap */}
  <Center max="md">...記事...</Center>  {/* 読み列 = 768px */}
</AppShell>
```

`layout="full"` で wrapper (px + max-w) を外すと **full-bleed** が可能になる。consumer が
`<Section>` (full-width 背景) + `<Center>` (読み列) で組む。背景を画面端まで伸ばす Landing 等で使う。

```tsx
<AppShell layout="full">
  <Section padding="lg" className="bg-surface-secondary">
    <Center max="xl">...hero...</Center>
  </Section>
</AppShell>
```

**なぜ contained を既定に残すか**: full-width canvas を既定にすると 1280 cap が消え、`<Center>` 忘れが
全ビューポート幅まで暴走する。それを防ぐ構造 lint は壊れやすく高コスト。contained 既定なら厳格 lint 不要
(scaffold + 本 docs で十分)。

## 別コンポーネントの方が適切な場面

| やろうとすること | 使うべき別コンポーネント | 理由 |
|---|---|---|
| 単列コンテンツの content max-width | `<Center>` | Center は content-level、AppShell は shell-level (= ページ全体) |
| 2 col / 3 col grid layout | `<TwoColumn>` / `<Grid>` | AppShell の中で grid を組む、AppShell 自体は単純 shell |
| Master-detail (固定幅 list + 流動 detail) | `<SplitPane>` | reservation 一覧の左 list / 右 detail 等の split は別 composite |
| full-bleed 背景 + 中央読み列 | `layout="full"` + `<Section>` + `<Center>` | contained の px+max-w wrapper を外し、背景を端まで伸ばす |

## アクセシビリティ

- **`<main>` の暗黙の役割**: AppShell は内部で `<main>` タグを使用、ページの主コンテンツ landmark を提供。consumer が `as="main"` で他に `<main>` を入れない運用を推奨 (1 ページ 1 main)
- **`<aside>` の sidebar**: PC sidebar slot は AppShell が `<aside>` でラップ、補助コンテンツ landmark として SR 認識
- **`<footer>` の footer**: footer slot は AppShell が `<footer>` (contentinfo landmark) でラップ。全ページ共通のサポートリンク / 著作権を SR が contentinfo として認識。consumer は中身を二重に `<footer>` で包まない (landmark のネストを避ける)。mobile では従来 `TopHeader` (= `<aside>` complementary) 内に埋もれていたフッター内容が footer slot に出ることで、モバイルでもフッター情報に到達できる (穴を塞ぐ)
- **bottomNav の semantic タグ**: BottomNav 中身を `<nav>` として実装するのは consumer 側、AppShell は外側 `<div className="lg:hidden">` でラップするだけ
- **skip-link**: AppShell に skip-link は内蔵していない、consumer 側で `<a href="#main">` 等を提供することを想定

## 関連

### 内部で利用するコンポーネント

なし。AppShell は素の `div / aside / main` を組み立てる shell composite。Phase A primitive (Center / Stack / Cluster) は内側 children として consumer 自由。

### AppShell を内部で使う代表的なコンポーネント / 使い方

- React Router の `<Outlet />` を `children` に渡し、route ごとに違う page を render する layout 用途
- multi-page SPA / SaaS app の app-level shell
- Setting / Profile 等の sub-app では `contentMax="narrow"` で控えめ shell に切替えても OK
