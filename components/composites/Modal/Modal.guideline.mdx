## 概要

ネイティブ `<dialog>` 要素 (`HTMLDialogElement.showModal()`) ベースの **モーダルダイアログ**。focus trap / Esc キー close / `::backdrop` overlay / 開閉時のフォーカス管理を **ブラウザ標準に委ねる** ため、自前実装より堅牢でメンテも軽い。compound component (`Modal.Body` / `Modal.Footer`) で構成。重要な確認 / 入力が必要 / アクションのコンテキストを集中させたい場面に。一時通知には `<Toast>`、画面内表示には `<Alert>` / `<EmptyState>` を検討。

### 別コンポーネントの方が適切な場面

| やろうとすること | 使うべき別コンポーネント | 理由 |
|---|---|---|
| **一時的な操作直後の通知** ("保存しました") | `<Toast>` | 自動消失・通知スタック対応、画面ブロックしない |
| **画面内の永続的なお知らせ** | `<Alert>` | 画面の一部 (inline) で表示、画面遷移を阻害しない |
| **空状態のメッセージ** | `<EmptyState>` | 画面の一部を埋める。Modal ほど強い遮断はない |
| **ページ全体の遷移** | (Routing) | URL が変わるなら別ページとして扱う |

## アクセシビリティ

- **ネイティブ `<dialog>` + `showModal()`**: focus trap / inert / Esc キー close / `::backdrop` overlay をブラウザ標準に委ねる (自前実装より堅牢)
- **`aria-modal="true"`**: 自動付与、SR がモーダルとして扱う
- **`aria-labelledby`**: title 指定時は自動配線、title 省略時は呼出側で id を渡す
- **focus 管理**: 開いた瞬間に内部の最初の focusable に focus (browser default)。閉じると元の trigger button に戻る
- **初期 focus の指定**: 既定では header の close ボタンが最初に focus される。確認ダイアログ等で Footer の primary アクションに focus を当てたい場合は、`initialFocusRef` prop にその `<Button>` の ref を渡す (開いた直後に上書きフォーカスする)。SR が先に主要操作を読むようになる
- **背景スクロールロック**: 開いている間は `document.body` の overflow を hidden にし、背後ページのホイール/スワイプスクロールを防ぐ (`showModal()` 単体では止まらないため Modal 側で制御)
- **キーボード操作**: `Tab` で trap、`Esc` で close (closeOnEsc=true 時)
- **overlay クリックでも close**: closeOnOverlayClick=true (default)。破壊的操作の確認では false に
- **close ボタン**: `<VisuallyHidden>` で SR 用テキスト「閉じる」を付与
- **`<dialog>` 要素の使えないブラウザ**: 主要ブラウザは対応済 (2022 以降)。古い WebView 等は polyfill 検討
