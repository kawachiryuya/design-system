## 概要

検索専用入力。アイコン + `<input type="search">` + クリアボタン + ローディングスピナーを組合せた Molecule。`Enter` キーで `onSearch` 発火、`Escape` でクリア + blur、value がある時にクリアボタンが自動表示される。検索 / フィルタリング / 候補絞り込みに使う。テキスト入力一般は `<Input>`、選択肢から選ぶ場面は `<Select>` / `<Radio>` を検討。

### 別コンポーネントの方が適切な場面

| やろうとすること | 使うべき別コンポーネント | 理由 |
|---|---|---|
| **一般的なテキスト入力** | `<Input>` | 検索特有の UI (クリアボタン / spinner / 検索アイコン) が不要 |
| **限定的な選択肢から選ぶ** | `<Select>` | テキスト入力ではなく排他選択 |
| **多数の候補から filter** (チェックリスト) | `<CheckboxGroup>` / Custom filter UI | 排他検索より複数 filter 向き |
| **フォーム送信に乗せる検索** | `<Input type='search'>` 直接 + form | SearchBar は自前 state 前提 |

## アクセシビリティ

- **`role="searchbox"`**: `<input type='search'>` で自動付与
- **`aria-label`** (推奨): 視覚的ラベルを持たないため、ariaLabel prop で「何の検索か」を SR に伝える
- **`aria-busy`** (loading 時): isLoading=true で自動付与
- **キーボード操作**:
  - `Enter`: `onSearch` 発火 (省略時は何もしない)
  - `Escape`: 内容クリア + blur
  - browser 標準の編集操作
- **クリアボタンの aria-label**: 「検索をクリア」固定
- **focus 表現**: border 色変化 + inset ring (input ベースの form control 共通パターン)
- **タッチターゲット**: sm (32px) / md (40px) / lg (48px)。lg で WCAG 2.5.5 (44×44px) 達成
