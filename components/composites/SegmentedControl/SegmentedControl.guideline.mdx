## 概要

排他的な選択肢を **横並びで常に全て表示** する UI (iOS の Segmented Control 風)。フィルター切替・表示モード切替 (リスト/グリッド)・少数 (2〜5 個) の排他的選択に適する。選択肢が多い場合や、選択肢の意味が長い場合は `<Select>` / `<Radio>` を検討。

---

## Props

SegmentedControl はジェネリック (`<T extends string | number>`) で値型を型レベルで保つ。

主な props:
- **items** (`SegmentedControlItem<T>[]`): `{value, label}` の配列。`label` は ReactNode 可 (アイコン併用 OK)
- **value** (`T`): 現在選択中の値 (controlled)
- **onChange** (`(value: T) => void`): 値変更コールバック
- **aria-label** (`string`): グループ用途を SR に伝える (推奨)

### 別コンポーネントの方が適切な場面

| やろうとすること | 使うべき別コンポーネント | 理由 |
|---|---|---|
| **多数の選択肢から 1 つ** (6 個以上) | `<Select>` / `<Radio>` | 一覧性ではなく省スペース・スクロール対応 |
| **オン/オフの 2 択** (設定) | `<Switch>` | 「ON/OFF」が明確に伝わる |
| **複数選択可能** | `<CheckboxGroup>` | 排他制御ではない |
| **絞り込みフィルタ (Modal 起動含む混在)** | `<FilterChip>` | Toggle / iconOnly / Modal 起動 etc. が混在する用途 |

## アクセシビリティ

- **`role="radiogroup"` + `aria-label`**: 外側の `<div>` がラジオグループ、各セグメントは `role="radio"` の `<button>`。「複数候補から 1 つを選ぶ排他選択」であることが SR に正しく伝わる (`aria-pressed` のトグルボタン群だと「独立した ON/OFF の集まり」と誤解される)
- **`aria-checked`**: 選択中のセグメントに `aria-checked="true"`、SR で「選択済み」と読まれる
- **キーボード操作 (roving tabindex)**: グループ全体で `Tab` 1 ストップ。`←` `→` `↑` `↓` で移動 = 即選択、`Home` / `End` で先頭 / 末尾へ。選択中の radio のみ `tabIndex=0` (未選択時は先頭)
- **focus ring**: 各 `<button>` に `focus-visible:ring-focus ring-inset` で 2px の inset focus ring。selected 時は ring 色を `surface` (白) に切替えて teal bg との contrast を確保
- **タッチターゲット**: 40px (h-10) 固定。WCAG 2.5.5 (44×44px) には僅か 4px 不足するが filter / view mode 用途の compact UI として標準値。WCAG 厳守が必要な context では親 container 側で touch area 拡張 (`p-1` 等) を推奨
