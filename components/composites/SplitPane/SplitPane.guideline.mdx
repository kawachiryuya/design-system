## 概要

**Master-detail layout** を提供する composite。固定幅 list pane + 流動 detail pane で、両 pane が独立スクロールする。**名前付き slot**: `list` prop が固定幅ペイン、`children` が detail。

- **mobile (< cols)**: 縦積み (両 pane が full width で順に表示)
- **PC (>= cols)**: grid `[listWidth]_1fr` で左右並び + 独立スクロール + 縦境界線 (optional)

予約一覧 / メッセージ受信箱 / 通知センター / ファイラー等、**list を選んで右で詳細を見る** UX に最適。`Router` の `<Outlet />` を `children` (detail) に渡す使い方が定番。

## Breakpoint 挙動

| viewport | 配置 |
|----------|------|
| **`< cols` (mobile/tablet)** | block layout: list と detail が縦積み、それぞれ通常の document flow |
| **`>= cols` (PC)** | `grid grid-cols-[listWidth_1fr]` + 固定高さ (`h-[height]`) + 両 pane `overflow-y-auto` |

切替点は **semantic breakpoint `cols:`** (既定 = lg / 1024px、preset で override 可)。TwoColumn と同じ列切替軸。

## consumer 側の責務

### 1. mobile での list / detail 表示制御

SplitPane は mobile で **両 pane を縦積みで表示**する。実際の master-detail UX (list を選んで detail を見る) では consumer 側で router state に応じて片方を `hidden cols:block` で隠す:

```tsx
// list + detail レイアウトの典型 pattern
<SplitPane
  listWidth="360px"
  list={
    /* detail 選択時は mobile で list を隠す */
    <div className="hidden cols:block">
      <ReservationsPage selectedId={selectedId} />
    </div>
  }
>
  <div ref={rightRef} key={selectedId}>
    <Outlet />
  </div>
</SplitPane>
```

### 2. detail 切替時の scroll-to-top

list の選択変更で detail pane が異なる内容に切り替わる時、scroll 位置を先頭に戻すのは consumer 側:

```tsx
const rightRef = useRef<HTMLDivElement>(null);
const prevId = useRef<string | null>(null);
useEffect(() => {
  if (selectedId !== prevId.current) {
    rightRef.current?.scrollTo({ top: 0, behavior: 'smooth' });
  }
  prevId.current = selectedId;
}, [selectedId]);
```

### 3. `height` の AppShell padding 連動

SplitPane の `height` は AppShell の main padding に応じて調整する:
- AppShell default (`py-container` = lg で 32px × 2 = 4rem): `height="calc(100vh - 4rem)"` (default 値)
- AppShell + subBar の場合は subBar の高さも引く必要あり

### 4. detail pane の force remount

URL params 等で detail を切り替える時、内部 state を resets するため `key` で remount:

```tsx
<SplitPane list={<List />}>
  <div key={selectedId}>
    <Outlet />
  </div>
</SplitPane>
```

## 別コンポーネントの方が適切な場面

| やろうとすること | 使うべき別コンポーネント | 理由 |
|---|---|---|
| 比率ベースの 2 列 (8/4 等) | `<TwoColumn>` | TwoColumn は比率 (fr テンプレート)、SplitPane は固定幅 + 流動 (master-detail UX) |
| Drawer のような開閉式 sidebar | (DS 未提供 — consumer 実装) | SplitPane は常時表示、開閉式は別 |
| ページ全体の app-level layout | `<AppShell>` | SplitPane は AppShell の main 内で使う想定の sub-layout |

---

## アクセシビリティ

- **semantic タグは consumer 責務**: list pane を `<aside>` や `<nav>`、detail pane を `<main>` 等で囲むのは consumer 側
- **focus 管理**: detail 切替時に focus を detail pane の先頭に飛ばす運用 (skip-link / `tabIndex={-1}` + ref focus 等) は consumer 側で実装
- **scroll 同期は無し**: 両 pane は独立スクロール、SR / keyboard 操作で list を移動しても detail は scroll しない。これは典型的な master-detail UX と一致

## 関連

### 内部で利用するコンポーネント

なし。SplitPane は `<div>` で構成される素のレイアウト composite。

### SplitPane を内部で使う代表的なコンポーネント / 使い方

- 予約一覧 / メッセージ受信箱 / 通知センター (list + detail UX)
- ファイラー / アセット管理 (folder/file tree + プレビュー)
- 設定画面のサブセクション選択 (左 menu + 右 form)
- `<AppShell>` の main 内で `<SplitPane>` を使う構成が典型 (`AppShell > main > Outlet (= SplitPane page)`)
