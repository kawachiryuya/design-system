export const Still = ({ toasts }) => {
  const Fire = () => {
    const { showToast } = useToast();
    const fired = React.useRef(false);
    React.useEffect(() => {
      if (fired.current) return;
      fired.current = true;
      toasts.forEach((t) => showToast(t));
    }, [showToast]);
    return null;
  };
  return (
    <ToastStoryContext.Provider value={{ frozen: true, inline: true }}>
      <ToastProvider>
        <Fire />
      </ToastProvider>
    </ToastStoryContext.Provider>
  );
};

## 概要

**いまの操作の結果を一言で**伝える一時的な知らせ。「保存しました」「送信できませんでした」のような 1 文に、操作を 1 つまで (「元に戻す」「再試行」) 添えられる。種類は `success` (できた) と `error` (できなかった) の 2 つで、見出しは無い。アプリの root に `<ToastProvider>` を置き、`useToast().showToast({ message })` で出す。置き場所 (画面の下の中央)・秒数 (できた 5 秒・操作つき 7 秒・できなかったは消えない)・枚数は部品が決め、使う側は選べない。画面に残しておく知らせは `<Alert>`、実行する前に確かめるのは `<ConfirmDialog>` を使う。

---

## Props

入口は 2 つ: `<ToastProvider>` の `children` と、`useToast().showToast(options)` に渡す `variant` / `message` / `action` (型は `ToastOptions`。`action` は `{ label, onClick }`)。下の表は両方をまとめて載せる。

### 別コンポーネントの方が適切な場面

| やろうとすること | 使うべき別コンポーネント | 理由 |
|---|---|---|
| **画面に残しておく知らせ** (お知らせ・注意・状態) | `<Alert>` | Toast は消える (できなかった、も閉じれば消える)。後から読み返すものは画面の中に置く |
| **警告・お知らせ・進み具合** ("残り 1 件です" "同期しています") | `<Alert>` / `<ProgressBar>` / `<Spinner>` | Toast は操作の結果 (できた・できなかった) だけを伝える |
| **実行する前に確かめる** ("削除しますか?") | `<ConfirmDialog>` | 元に戻せる操作は確かめずに実行し、Toast の「元に戻す」を出す方が流れを止めない |
| **別の画面への案内** | 本文の `<Link>` | Toast の操作は、その結果に対する短い操作 (「元に戻す」「再試行」) だけ |
| **FormDialog の中の入力の誤り・保存の失敗** | dialog の中の `<Alert>`・欄のエラー (`error`) | 直す場所のそばに、直すまで残す |

## アクセシビリティ

- **読み上げ**: Provider は `role="status"` (`aria-live="polite"`) と `role="alert"` (`aria-live="assertive"`) の 2 つの入れ物を空でも常に置き、できた、は status (区切りを待つ)、できなかった、は alert (すぐ) に入れる。見出しが無いので、文 1 つがそのまま読まれる
- **秒数と止まる (WCAG 2.2.1)**: できた、は 5 秒・操作つきは 7 秒で消える。触れている間・マウスが乗っている間・中にフォーカスがある間は残り時間を止め、離れたら残りから再開する。できなかった、は消えない
- **閉じる**: できなかった、にだけ「閉じる」の文字のボタンがあり、読み上げ名は「通知を閉じる」(dialog の中に出たとき、dialog の閉じると名前が重ならないように)。できた、は閉じるボタンを持たない (自動で消える。下へ払っても消える)
- **下へ払う**: 下へ 24px より多く動かして離すと消える (できたも、できなかったも)。ボタンの上から始めた操作は払う動きにしない。動きを減らす設定では、出入りの動きを無くす
- **フォーカスの戻り**: Toast の中にフォーカスがあるまま閉じる・消えるときは、出したときにフォーカスがあった要素に戻す。その要素が消えた・押せない (dialog の後ろ) ときは、Toast に入る直前の要素へ、それも無ければ Toast がいる dialog へ戻す (body に落とさない)。指・マウスで閉じたときは、戻した要素に、次にキーが押されるまで輪を出さない
- **フォーカスの輪**: Toast の中のボタンは、濃い面・赤い面の上で見えるよう、白い内側の輪 (`focus-ring-on-fill`)
- **押せる大きさ**: ボタンは高さ 44px 以上
- **Tab の順**: Toast は Provider の位置 (アプリの root ならページの最後) に入る。出てもフォーカスは移さない
- **dialog を開いている間** (ConfirmDialog・FormDialog・狭い幅の Menu・Popover の下から出る面): ブラウザは一番上の dialog の外を押せなくし、読み上げからも外す。そこで Toast の置き場は、開いている間だけ**一番上の dialog の中**へ移り、一番上の層に出る (見える・押せる・フォーカスが入る・読み上げられる。使う側は何もしなくてよい)。Tab の巡りでは dialog の最後に入る。dialog を閉じると置き場は元の場所へ戻り、出ている Toast と残り時間はそのまま。指・マウスで開いた dialog の中でも、Toast の中でキーを押せば輪が出る。下から出る面が閉じる動きの間 (200ms) だけは、中の Toast も押せない
- **どの dialog が一番上か**: Toast は、ページで最初の ToastProvider が描かれてから開いた dialog の順を覚える。それより前から開いていた dialog の順は分からないので、フォーカスを含む dialog を一番上とみなす。ToastProvider をアプリの root に置けば、順はいつも正しい
- **下のものに重なる**: 下のナビ (AppShell)・FormDialog のフッターは避けずに重ねる。できなかった、は閉じるまで残るので、狭い幅で画面いっぱいの FormDialog を開いている間は、確定のボタンに重なる。dialog の中の知らせは dialog の中の `<Alert>` に出す
