## 概要

操作直後の **一時的なフィードバック通知**。「保存しました」「エラーが発生しました」のような短いメッセージを画面の端 (top / bottom / right) に表示し、`duration` 秒後に自動消滅する。永続的な画面内通知は `<Alert>`、確認が必要な操作は `<Modal>`、空状態は `<EmptyState>` を使い分ける。

---

## 利用形態

Toast は 2 つの API を持つ:

**1. 単発 controlled** (`<Toast />` 直接利用): 親が `open` / `onClose` を管理。シンプルだが 1 つだけ。

**2. ToastProvider + `useToast()`** (推奨): アプリ全体を `<ToastProvider>` でラップし、内部から `useToast().showToast({...})` で呼出。**複数 Toast のスタック管理 / 自動消滅 / 位置統一が自動**。

```tsx
// Provider (アプリ root)
<ToastProvider position="top-right" maxToasts={3}>
  <App />
</ToastProvider>

// 呼出 (任意 component 内)
const { showToast } = useToast();
<Button onClick={() => showToast({ variant: 'success', description: '保存しました' })}>保存</Button>
```

### 別コンポーネントの方が適切な場面

| やろうとすること | 使うべき別コンポーネント | 理由 |
|---|---|---|
| **永続的な画面内通知** | `<Alert>` | Toast は自動消滅、永続表示は Alert |
| **確認が必要な操作** ("削除しますか?") | `<Modal>` | フォーカストラップ + 確定/取消 |
| **データなしの代替表示** | `<EmptyState>` | 画面の一部を埋める用途 |
| **ステータスを 1 単語で** | `<Badge>` | アクション通知ではなく状態表示 |

## アクセシビリティ

- **`role="alert"`** (error variant): aria-live="assertive" 自動付与、SR が即時読み上げ
- **`role="status"`** (それ以外): aria-live="polite" 自動付与、SR が次の文末で読み上げ
- **close ボタン**: `<VisuallyHidden>` で「閉じる」を SR 用テキストで付与
- **focus 管理**: 自動消滅 / overlay ではないため focus trap なし。トリガー (button 等) の focus はそのまま
- **キーボード操作**: close ボタンに Tab で focus 可、Enter / Space で発火
- **autohide の停止**: pause-on-hover は実装未対応 (将来検討)。長文 / 重要な情報は duration=0 で手動 close へ
- **動画 / 強い色変化を避ける**: 視覚に敏感なユーザーへの配慮
