## 概要

2 列レイアウト (main + sidebar) を **mobile 縦積み → PC 横並び grid** で表現する composite。`children` が main、**名前付き `sidebar` prop** が副次領域 (AppShell と同じ slot 流儀)。位置依存 children を廃し、順序取り違えを原理的に防ぐ。`sidebar` 省略で単一カラム。

`split` 比率 (`6/6` / `7/5` / `8/4` / `9/3`、既定 `8/4`) は **fr テンプレート** (`grid-cols-[2fr_1fr]` 等) に compile-down され、生の col-span は露出しない。gutter は `grid.gutter` トークン固定。`mobileReverse` で mobile 表示順を視覚反転 (DOM 順は不変)。

## split 比率と用途

| split | fr テンプレート | main / sidebar | 想定用途 (consumer) |
|-------|-----------------|----------------|---------------------|
| `6/6` | `1fr 1fr` | 50 / 50 | Search (form + preview) |
| `7/5` | `7fr 5fr` | 58 / 42 | やや main 寄りの 2 領域 |
| `8/4` | `2fr 1fr` | 66.7 / 33.3 | **既定**。Results / Seat / SeatMap (main + sidebar) |
| `9/3` | `3fr 1fr` | 75 / 25 | 細い sidebar |

**fr テンプレートに統一した理由**: 旧 `7/3` は 12-col grid に乗らず (10-col grid という異物だった)。`6/6`〜`9/3` を 12-col 整数比率の **fr テンプレート** (`grid-cols-[Xfr_Yfr]`) で表現することで、生 `grid-cols-N` / `col-span` が系から消え、SplitPane の `grid-cols-[var(--sp-cols)]` と作法が統一される。gutter を引いた後の比率も fr が自動調整する。

## Breakpoint 挙動

| viewport | 配置 |
|----------|------|
| **`< cols` (mobile/tablet)** | `flex flex-col` で main → sidebar の縦積み (各 full width) |
| **`>= cols` (PC)** | `grid` + fr テンプレートで横並び、main 左 + sidebar 右 |

切替点は **semantic breakpoint `cols:`** (既定 = lg / 1024px、preset で override 可)。AppShell の `shell:` と分離されており、列切替点だけを別途調整できる。consumer の `cols:sticky` で「2 カラム化と sticky を同期」できる。

## mobileReverse の使い分け

`mobileReverse=true` で main (`children`) と sidebar (`sidebar` prop) の **mobile 表示順を視覚反転** (DOM 順は main→sidebar 固定のまま、CSS `order` のみ):

| mobileReverse | mobile | PC |
|---------------|--------|----|
| `false` (default) | main 上 → sidebar 下 | main 左 + sidebar 右 |
| `true` | sidebar 上 → main 下 | main 左 + sidebar 右 |

**使い所**:
- SearchPage: `mobileReverse=true` で「**form (main) は下、preview (sidebar) は上**」にして、mobile UX で「検索条件を見てから入力する」流れに最適化
- 大半のケースは `false` (mobile = PC と同じ DOM 順)

## 別コンポーネントの方が適切な場面

| やろうとすること | 使うべき別コンポーネント | 理由 |
|---|---|---|
| 単列コンテンツの max-width | `<Center>` | Center は単列、TwoColumn は 2 col 構造 |
| Master-detail (固定幅 list + 流動 detail) | `<SplitPane>` | TwoColumn は比率ベース (fr テンプレート)、SplitPane は固定幅 + 流動の master-detail UX |
| 反復カード / 3 col 以上の grid | `<Grid>` (minItemWidth / cols) | TwoColumn は 2 領域の比率専用、反復・N-up は Grid |
| grid 上の中央寄せ単列 | `<Center max="md">` 等 | 揃える相手の共有 grid が無ければ centered は Center に畳む |
| sidebar を sticky 表示 | `<TwoColumn split="8/4">` + sidebar の className で `cols:sticky cols:top-4` | sticky は **consumer 側で適用**、`cols:` で列切替と同期。TwoColumn は配置のみ責務 |

## アクセシビリティ

- **semantic タグは consumer 責務**: TwoColumn は中身を wrap する `<div>` のみ、main を `<main>` / sidebar を `<aside>` 等で囲むのは consumer 側で行う (1 ページの semantic 構造は consumer のみが知る)
- **reading order**: DOM 順 = main → sidebar、`mobileReverse` 使用時も DOM 順は変わらず CSS の `order` のみ反転。SR は DOM 順で読み上げるので、`mobileReverse=true` でも main を「主役」として認識する
- **`order` 反転の注意**: visual order と DOM order が乖離すると認知的負荷が増えるため、`mobileReverse` は必要な場面 (mobile UX 最適化) のみで使う

## 関連

### 内部で利用するコンポーネント

なし。TwoColumn は `<div>` で構成される素のレイアウト composite。

### TwoColumn を内部で使う代表的なコンポーネント / 使い方

- 検索結果 ページ (Results pattern) — `split="8/4" sidebar={<条件>}` で list + 条件 sidebar
- 座席選択ページ (Seat pattern) — `split="8/4" sidebar={<料金>}` で seat picker + 料金 sidebar (`cols:sticky` で固定)
- 予約検索ページ (Search pattern) — `split="6/6" mobileReverse sidebar={<preview>}` で form + preview
- AppShell の main 内で TwoColumn を組合せる構成が典型 (`<AppShell><Outlet /></AppShell>` → 各 page で `<TwoColumn>...</TwoColumn>`)
