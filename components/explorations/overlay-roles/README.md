### 引いて閉じるで分かったこと

1. **掴む領域を上端の帯に絞ると、本体の操作とぶつからない。** 本体は `touch-action` を変えていないので、行の上で引くとブラウザのスクロールの扱いになり (タッチでは pointercancel)、行も押されない。マウスでも、押した行と離した場所が違うので押したことにならない
2. **開く動き (animation) と引く位置 (transform) は同じ transform を取り合う。** 開く動きは `[open]` が付いたときにだけ再生されるので、引く・戻す・抜けるで animation の指定には触らず、位置は `--x-sheet-drag`、離した後の動きは `data-drag="settle"` の transition だけで付けた。開く動きの途中で掴んだときは、その動きを終わらせてから指に付ける
3. **マウスでシートの中を押して背景で離すと、閉じる (今までもそう)。** 背景を押して閉じる判定が「click の対象が `<dialog>` そのものか」なので、中で押して外で離すと、click が両方を含む `<dialog>` に届く。Modal (出荷する部品) も同じ判定で、中央のカードでも見出しを押して背景で離すと閉じた。引いて閉じる (`handle=2`) の帯は pointer capture をしているので、これは起きない。タッチでは起きなかった
4. **reduced-motion の下では、どの要素にも 0.01ms の transition が付いている** (preset が全要素に `transition-duration: 0.01ms !important` を当てるため。transition-property の既定は all)。離した直後の 1 フレームだけは前の位置が見える。体感では即時
5. **自動操作では「速く払う」を作りにくい。** CDP の往復に 1 回 30ms ほどかかるので、ふつうに送ると 27px の払いが 90ms になり、速さ 0.30〜0.49px/ms で「戻る」になった。入力の時刻を指定して送ると閉じた。実機の指の速さで 0.5px/ms がどう感じられるかは見ていない

## 作って分かったこと

実際に起きたことだけ。番号は上の表から参照している。

1. **「選ぶ」を中央のカードで作ると、選んだら閉じる、にできない。** Radio は矢印キーで選び直すたびに change が起きるので、change で閉じるとキーボードでは 2 つ目を選べない。そのため「決定」ボタンが要り、二手になる。下から / 近く の形は「行を押す = 選ぶ」なので一手で閉じる
2. **DropdownMenu に選択中の印が無い。** 項目は `role="menuitem"` だけで `menuitemradio` / `aria-checked` を持てない。検討では label の中にチェックの印と読み上げ用の「（選択中）」を手で入れた。チェックの印に使えるアイコンも登録簿に無い (`check_circle` はあるが単体の `check` が無い) ので、パスを直接書いた
3. **押した要素の近くの形は、指で押すには小さい。** DropdownMenu の項目は高さ 37px (`py-2` + 14px の文字)、FilterChip は 32px (h-8)。どちらも 44px に届かない。下から出る形の行は 48px にした
4. **Popover は、離れても閉じない。** Tab でパネルの外の要素に移っても、背景をスクロールして入口が画面の上へ消えても、パネルは開いたまま (入口について画面の外へ出る)。狭い幅では入口がすぐ画面の外へ流れるので、補足を「近く」で出すと、開いたものがどこにあるか分からなくなりやすい
5. **ActionBar は狭い幅のフッターで縦に積まれる。** 「取り消し」「適用」が 2 段になり、下から出る形のフッターが 129px になる (作業の高さ 690px のうち 2 割)。ActionBar は container 幅 400px 未満で縦にする決まりなので、フッターでは横に固定したいかもしれない (判断はしていない)
6. **ActionBar を Modal.Footer に入れると幅が 0 になる。** Modal.Footer は flex で、ActionBar の外側は `@container` (inline-size) なので、幅を持たせないと縮む。検討では `className="w-full"` を付けた
7. **Modal の閉じるボタンは 40px。** Modal は `size="sm"` の iconOnly を使っていて 44px に届かない。下から出る形では `size="md"` (48px) にした
8. **名前で呼んだ Icon は、ボタンの中でも読み上げられる。** `<Icon name="remove" />` は登録簿のラベル (「減らす」) を `aria-label` に持つので、ボタンの名前が「減らす 予約をキャンセル」になる。Icon の JSDoc の「label を省略すると aria-hidden」と食い違う。検討では文字の隣のアイコンに `aria-hidden` を付けた
9. **FilterChip を選ぶの入口にすると、押しっぱなしの意味が混ざる。** FilterChip は常に `aria-pressed` を持つので、DropdownMenu の入口にすると `aria-pressed="false"` と `aria-haspopup="menu"` が同時に付く

## 仮に決めたこと

検討のために決めたもの。どれも出荷の決まりではない。

- 狭い幅と広い幅の境目は 640px (Tailwind の `sm`)
- 下から出る形: 土台は `<dialog>` の `showModal()`。背景の色は Modal と同じ (`surface.overlay`)。上の角だけ `rounded-md`。高さは中身なり・上限 85dvh。本体だけスクロール (`overscroll-contain`)。見出しは `type-section-title`、閉じるボタンは 48px (`Button size="md" iconOnly`)
- 画面いっぱい: 100dvh・角なし。見出しと閉じるが上、フッターが下に固定
- 開く動きは下から 200ms (`--duration-normal`・`--easing-out`)。`prefers-reduced-motion: reduce` では動かさない (確認済み)。閉じる動きは無し
- 背景のスクロール止めは `html` と `body` の両方に `overflow: hidden` (Modal は `body` だけ)
- 閉じたらフォーカスを開く前の要素に戻す (ブラウザも戻すが、明示もする)
- 確認は、Esc では閉じる・背景を押しても閉じない
- 選ぶの行: 高さ 48px 以上。選択中は右にチェック (`onSurface.primary` 相当の色) と読み上げ用の「（選択中）」。操作の一覧 (予約を変更) は印なし
- 下端の余白は `env(safe-area-inset-bottom)` を足す (下の「確かめられなかったこと」)
- 引いて閉じる (`handle=2`):
  - 効くのは `form="sheet"` かつ背景を押して閉じるシートだけ。確認と画面いっぱいでは、つまみは見た目だけ (画面いっぱいでは出さない)
  - 掴めるのは上端の帯 (つまみの行と見出しの行) だけ。閉じるボタンの上では掴まない。本体は引いても動かない
  - 掴む領域は `touch-action: none` と `select-none`。Pointer Events で pointerdown のときに capture
  - 位置は CSS 変数 `--x-sheet-drag` (下へだけ。上へは動かさない)。引いている間は動きなし
  - 離したとき、引いた距離が高さの **25%** を超える、または下向きの速さが **0.5px/ms** を超える → 下へ抜けて閉じる (200ms・easing out の後に onClose)。それ以外 → 元へ戻る (200ms)。速さは直近 100ms の動きで測る
  - pointercancel (ブラウザが指を取り上げたとき) は、距離によらず元へ戻す
  - reduced-motion では、抜ける・戻る動きを付けずに即時
  - つまみは `aria-hidden`、フォーカスも受けない。代わりの手段は閉じるボタンと Esc
- 開いた直後のフォーカスはブラウザ任せ (最初の要素 = 閉じるボタン)
- 中央のカードで選ぶ「並び順」は Radio + 取り消し / 決定、「予約を変更」は secondary の Button を 4 つ
- 帯と切り替えは検討用の見た目 (warning の薄い面と破線) で、題材の画面と混ぜない

## 置き場と検査

`components/explorations/` は検査の外ではなかった (この検討はすべて通した)。

- lint: story の文字の直書き禁止 (`type-*`) が `components/**/*.stories.tsx` として掛かる。`Sheet.tsx` / `options.ts` は出荷コンポーネントと同じ規則 (生 hex・文字の直書き・フォーカスの直書きの禁止) が掛かる
- `check:utilities`: 出荷側からは外れている (`/^components\/explorations\//`) が、story の className は Storybook の CSS と突き合わされる (`bg-bg-default` と `min-h-11` が落ちたので直した)

## 確かめられなかったこと

- スマホの実機 (iOS Safari / Android Chrome) では触っていない。確かめたのは Chromium (Playwright) だけ
- 背景のスクロール止めはホイールで確かめた。指で引く操作 (touch) では確かめていない。iOS Safari は `overflow: hidden` だけでは止まらないことがある
- `env(safe-area-inset-bottom)`: Storybook の iframe の viewport に `viewport-fit=cover` が無いので、この画面では 0 のまま効かない。ホームバーのある端末での見え方は未確認
- 読み上げ (VoiceOver / TalkBack) は使っていない。axe (test-storybook) は閉じた状態の画面だけを見て違反 0
- `DropdownMenu` / `Popover` の flip / shift (画面の端で向きを変える) は確かめていない。予約を変更は画面の下の方にあるので、はじめから上に出す指定 (`placement="top-start"`) にした

- 引いて閉じる: 実機の指の感じ (25% と 0.5px/ms が重い・軽い、引き始めの反応)。iOS Safari の画面の下端・左端のジェスチャー (ホームに戻る・戻る) との取り合い。Android の戻るジェスチャーとの取り合い
- 引いて閉じる: シートの中身が長く本体がスクロールする状態 (作業の「下から」も対象になる) で、帯を引くときの感じ。確かめたのは中身の短い「並び順」と「自由席について」だけ
- 引いて閉じる: 読み上げを使っているときの操作 (つまみは読み上げに出さない前提)
