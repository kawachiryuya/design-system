## 概要

ステータス・カテゴリ・数値カウントなどを簡潔に示す **非 interactive なインラインラベル**。`<span>` ベースで状態 (hover / focus / active) を持たない。押せる UI が必要なら `<Button>` / `<Link>`、削除可能なタグなら `<FilterChip>` を使う。

### 別コンポーネントの方が適切な場面

「これは Badge じゃないかも?」と迷ったときは下の表で目的に合うコンポーネントを探す:

| やろうとすること | 使うべき別コンポーネント | 理由 |
|---|---|---|
| 押すと **アクションが起きる** | `<Button>` | キーボード操作・focus・role="button" を備えた専用コントロール |
| 押すと **URL に遷移** する | `<Link>` | `<a>` でないと OS 機能 (右クリック新タブ等) / SEO が効かない |
| **削除可能なタグ** (チップ) | `<FilterChip>` | 削除・選択トグルを持つフィルタ用 UI、Badge は非 interactive |
| **インラインのお知らせ** (1 文以上) | `<Alert>` | 長文と icon + テキストの組合せに最適化、Badge は短文専用 |
| **一時的なフィードバック** (操作直後の通知) | `<Toast>` | 自動消失・通知スタック対応 |

## アクセシビリティ

- **role なし**: `<span>` のテキストそのものが意味を伝える前提。SR は通常テキストとして読み上げる
- **色だけに頼らない**: テキスト + (任意で) `dot` の二重補強。WCAG 1.4.1 (色の使用) に沿う
- **コントラスト**: 全 variant × appearance の組合せで前景/背景が semantic token (`text-onSurface-*` / `bg-surface-*`) を参照し、WCAG AA を満たす設計
- **数値カウントの読み上げ**: `<Badge>12</Badge>` 単独だと「12」とだけ読まれる。親要素で文脈を補完するか、`aria-label` を付けて `<Badge aria-label="未読 12 件">12</Badge>` のように補強する
- **dot は装飾**: `aria-hidden="true"` を自動付与。色情報は SR に伝わらないため、テキストでステータスを表現する

関連: [Semantic Colors](?path=/docs/principles-color-semantic-colors--docs)
