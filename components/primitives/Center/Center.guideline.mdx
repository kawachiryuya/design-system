## 概要

単列コンテンツの水平センタリング (max-width + mx-auto) を担う layout primitive。`max` で 4 段階の最大幅 (`form` 448 / `reading` 768 / `wide` 896 / `marketing` 1024) を use-case 名で指定する。垂直 padding やセクション間 spacing は持たず、`className` 経由 (`py-12` 等) や Stack primitive で別途与える単機能設計。

**AppShell の shell-level max-width (1280px) とは別軸**。AppShell が「ページ全体の左右余白を作る」のに対し、Center は「ページ内のコンテンツ自身を読みやすい幅に絞る」役割で、両者は入れ子で同時に効く。

### 別コンポーネントの方が適切な場面

| やろうとすること | 使うべき別コンポーネント | 理由 |
|---|---|---|
| ページ全体の左右余白を作る | `<AppShell>` (Phase B 予定) / `max-w-container-default` utility | Shell-level の 1280px max-width は AppShell の責務、Center は content-level |
| 2 列 (main + sidebar) レイアウト | `<TwoColumn>` (Phase B 予定) | Center は単列専用、複数 col 配置は別 composite |
| 内側要素の垂直 spacing | `<Stack>` (Phase A 予定) / `space-y-*` utility | Center は spacing を持たない、垂直方向は Stack に委譲 |
| アイコン + テキスト等の inline 配置 | `<Cluster>` (Phase A 予定) / `flex items-center gap-*` | Center は block 単列、inline 配置は別 primitive |

## アクセシビリティ

- **semantic タグ**: `as` prop で `div / section / article / main` を切り替え。Article / FAQ 等は `as="article"` で SR / skip-link / browser reader-mode の認識を保つ
- **max-width と reading**: `max="reading"` (768px) は **WCAG 1.4.8 (Visual Presentation)** が推奨する「1 行 80 文字以下」を自然に満たす。記事本文には必ず `reading` 以下を選ぶ
- **`<main>` の重複**: `as="main"` を 1 ページに複数置くと SR の landmark navigation が壊れる。`<main>` は AppShell 配下で 1 つだけにする運用を consumer 側で担保する

## 関連

### 内部で利用するコンポーネント

なし。Center は単独で完結する Layout primitive。

### Center を内部で使う代表的なコンポーネント / 使い方

- `<AppShell>` (Phase B) の main slot 内 — page-level の単列コンテンツに使う
- Login / Signup / Settings — `max="form"` + `className="py-12"`
- Article / FAQ / 規約 — `as="article"` + `max="reading"`
- Help (内側 grid 反復) — `max="wide"` + 内側 `grid-cols-2`
- Landing / Card grid (max 3 col) — `max="marketing"`
