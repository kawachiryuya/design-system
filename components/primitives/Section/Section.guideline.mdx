## 概要

ページの**縦リズム (section 分割)** を担う layout primitive。`<section>` 意味タグ + `py-section-*` padding を第一級概念にする。`padding` (`none`/`sm`/`md`/`lg`) は必須。

**横幅制約は持たない (full-width 既定)**。読み列の幅は内側の [`<Center>`](?path=/docs/primitives-center--guideline) が所有する。この責務分離が肝で、Section が full-width のままなので、将来 `background` を optional 追加するだけで「**full-bleed 背景 + 中央 max-width コンテンツ**」が `bleed` prop 無しで成立する。

グループ内の細かい間隔は [`<Stack>`](?path=/docs/primitives-stack--guideline) (gap)、ページ構造の section 分割は Section (padding)、とスコープで責務分離する。

### 別コンポーネントの方が適切な場面

| やろうとすること | 使うべき別コンポーネント | 理由 |
|---|---|---|
| 読み列の max-width 制約 | `<Center>` | 横幅は Center の責務、Section は縦リズムのみ |
| グループ内の要素間 gap | `<Stack>` | 4〜24px のグループ内間隔は Stack。Section は 32px+ の page section |
| ページ全体の骨格 (header/nav/main) | `<AppShell>` | Section は main 内の 1 区画、ページ全体構造は AppShell |
| 反復カード / 2 列配置 | `<Grid>` / `<TwoColumn>` | Section は単一区画の縦余白のみ |

## アクセシビリティ

- **`<section>` は landmark**: 既定の `as="section"` は landmark role を持つ。複数並べるときは `aria-label` / `aria-labelledby` で名前を付ける (無名 landmark の連続は SR navigation を損なう)。装飾的な区切りで landmark 不要なら `as="div"`
- **`<main>` の重複禁止**: `as="main"` は 1 ページ 1 つ。AppShell 配下では AppShell 側の main と二重にならないよう注意
- **見た目でなく構造で分ける**: section の境界は padding (空白) で示すが、SR には空白は伝わらない。意味的なまとまりは `aria-label` + 内部の見出し (`<h2>` 等) で担保する

## 関連

### 内部で利用するコンポーネント

なし。Section は単独で完結する Layout primitive。

### Section と組合せる代表的なコンポーネント / 使い方

- `<Center>` — Section (full-width) の内側で読み列を絞る基本の組合せ
- `<AppShell layout="full">` の main 内 — Section (背景) + Center (読み列) で full-bleed ページを組む
- Landing / marketing ページ — 交互の背景色 section を `<Section padding="lg" className="bg-*">` で
