## 概要

読み込み中のコンテンツの形状を予告する placeholder。長時間処理 (3 秒以上目安) で **「何が読み込まれるか」を視覚的に伝える** ことで、ユーザーの待ち時間体感を短縮する。`role="status"` + `aria-busy="true"` 自動付与で SR にも「読み込み中」を伝える。

4 形状 (text / circular / rectangular / rounded) を組み合わせて実コンテンツのレイアウトに近似させる。短時間処理 (1〜2 秒) には Skeleton ではなく **Spinner** が適切。

### 別コンポーネントの方が適切な場面

| やろうとすること | 使うべき別コンポーネント | 理由 |
|---|---|---|
| 1〜2 秒の短時間処理 | `<Spinner>` | 形を予告するメリットが薄い時間スケール |
| 進捗 % が分かる処理 | `<ProgressBar>` | 推定残り時間と完了を伝えられる |
| データなしの空状態 | `<EmptyState>` | 読み込みではなく「ない」を伝えるなら専用 |
| エラー状態 | `<Alert>` | 読み込み失敗の通知は Alert |

## アクセシビリティ

- **`role="status"`**: SR は live region として認識
- **`aria-busy="true"`**: 「処理中」を SR に伝える。読み込み完了後に DOM を差し替えれば自動的に解除される
- **`aria-label="読み込み中"`**: SR で文脈を伝える
- **コントラスト**: `bg-surface-skeleton` (`#e5e5e5`) は背景白に対して 1.4.11 (3:1) ギリギリ。視認性が必要なら明示的に CSS でコントラスト調整
- **`prefers-reduced-motion`**: 未対応 (AAA 案件、別タスク)。アニメーション過敏ユーザー向けに `animated={false}` で opt-out 可能

## 関連

### 内部で利用するコンポーネント

なし。Skeleton は単独で完結する Primitive (div + style 属性で図形を描画)。

### Skeleton を組み合わせる代表的なコンポーネント

- `<Card>` のローディング状態 — 画像 + アバター + テキスト + ボタンの合成
- リスト系コンテンツのローディング — Avatar + テキスト 2 行 + チップの 4-N 行繰返し
- 記事/詳細ページのローディング — タイトル + 著者 + ヒーロー画像 + 本文の合成
