# Tokens Overview

このデザインシステムの token は **2 層構造** で設計されています。普段の実装では **Semantic 層を優先** して使い、Primitive 層は palette 拡張やトークン追加時の参照に使います。

---

## 2 層構造

```text
┌─ Primitive (Global) ────────────────────────────┐
│  値そのものを定義する数値・色値のレイヤ          │
│  プロダクトに依存しない、変更で全体に影響         │
│                                                  │
│  例: color.primary.700  →  "#006F50"             │
│      spacing.4          →  "16px"                │
└──────────────────────────────────────────────────┘
                  ↓ Style Dictionary が参照
┌─ Semantic ──────────────────────────────────────┐
│  「役割名」で参照する意味付けのレイヤ            │
│  下流 product で意図のままブランド override 可能 │
│                                                  │
│  例: color.surface.primary  →  color.primary.700 │
│      typography-semantic.heading.xl → font-size.4xl  │
└──────────────────────────────────────────────────┘
                  ↓ Style Dictionary build
┌─ Tailwind utility classes ──────────────────────┐
│  bg-surface-primary / text-onSurface-muted      │
│  gap-component-md / text-heading-xl 等           │
└──────────────────────────────────────────────────┘
```

semantic 層の元データでは Style Dictionary の参照記法 `<code>&#123;color.primary.700&#125;</code>` のように curly brace で primitive を指します。Storybook 上では読みやすさのため `→` で表記しています。

---

## いつどっちを使う?

| 場面 | 使うレイヤ | 例 |
|---|---|---|
| **コンポーネント実装** (大半のケース) | **Semantic** | `bg-surface-primary` / `text-onSurface-muted` |
| 既存 semantic に該当がないが汎用パレットから引きたい | (新しい) Semantic を追加 | `bg-surface-tertiary` を新設 |
| product 側でブランドカラーを変えたい | Semantic を override | `surface-primary` を別 hex に |
| 拡張・整理のため palette 全体を見たい | **Primitive** で参照 | `primary.50〜900` を確認 |

**禁則**: 実装で `bg-teal-700` のような **primitive 直参照は禁止** ([AGENTS.md §3 トークン参照ルール](https://github.com/kawachiryuya/design-system/blob/main/AGENTS.md#3-トークン参照ルール) 参照)。理由は下流 product のブランド override が効かなくなるため。

Spacing は component 内部余白のための数値スケールで、page-level の layout frame (大外 padding / section 間隔 / 12-col grid) は **Layout token** が担当します ([Tokens/Layout](?path=/docs/tokens-layout--guideline) 参照)。

Radius / Shadows / Animation / Breakpoints は **semantic 層を持たない** = primitive 直参照運用です。将来用途別の意味付けが必要になった時点で追加する想定 (例: `radius-semantic.card → radius.md`)。

Z-Index / Opacity / Focus Ring は逆に **primitive 層を持たず semantic 名のみ** の運用です。これらは「具体値」より「役割名」で意図が伝わる種類のスケール (例: `z-modal` のほうが `z-1300` より読みやすい)。

**なぜ 2 層にしないか**: これらは color/spacing と違って **palette 的に再利用される primitive 層が概念上存在しません**。`z-index = 1000` 自体に意味はなく「modal レイヤ」という役割で初めて意図が立ち、`opacity` は連続値 (0.0〜1.0) で palette 化に意味がなく、`focus-ring` は 1〜2 値しかありません。無理に primitive 層を挟むと `z-index.layer-1: 1000` のような中継が増えるだけで価値がない、という判断です。詳細は [AGENTS.md §3-4](https://github.com/kawachiryuya/design-system/blob/main/AGENTS.md#3-4-semantic-only-スケール-z-index--opacity--focus-ring) 参照。

### サイズスケールの `md = default` 規約

`radius` / `shadow` のような size label 系カテゴリは、**中核を `sm / md / lg` の 3 段に揃え、`md` をカノニカルなデフォルト値** としています。`tokens/preset.cjs` の `DEFAULT: md` エイリアスにより、bare 形 (`rounded` / `shadow`) も `md` に解決されます。`xs` や `xl` のような外側の段は、source token 純度を保つためデフォルトでは持たず、必要が出た時点で追加する方針です。詳細は [AGENTS.md §3 サイズスケール内の `md = default` 規約](https://github.com/kawachiryuya/design-system/blob/main/AGENTS.md#サイズスケール内の-md--default-規約) 参照。
