# フィードバックの原則

## メタ情報
- カテゴリ: インタラクション原則 > Feedback
- 適用範囲: Atom〜Page
- ステータス: Approved
- 最終更新: 2026-06-02

## 原則の定義

**ユーザーの操作に対して「何が起きたか / 起きているか / 起きうるか」を即時に可視化する**

操作の結果が見えないと、ユーザーは「ボタンを押し直すべきか」「処理が止まったのか」を判断できず、不安と誤操作を生む。
すべての操作にはフィードバックが必要であり、その表現は「時間性 × 場所 × 対象」の 3 軸で選び分ける。

## なぜフィードバックが必要か

- **不確実性の排除**: ユーザーは自分の操作が届いたかを常に検証している
- **誤操作の防止**: 同じボタンを何度も押す / 別の操作を上書きする等を防ぐ
- **信頼の形成**: 結果が見えるシステムは信頼され、見えないシステムは離脱を招く
- **アクセシビリティ**: 視覚に依存しないフィードバック (`aria-live` 等) が必要なユーザーにも結果を届ける

## 4 種のフィードバック

| 種別 | いつ使う | 代表的なコンポーネント | 詳細 |
|---|---|---|---|
| **即時通知** | 操作の結果を一時的に伝える (保存完了 / コピー完了等) | Toast, Snackbar | [Toast Notifications](./toast-notifications.mdx) |
| **待機状態** | 処理中であることを伝える (1〜10 秒の待機) | Spinner, Skeleton | [Loading Indicators](./loading-indicators.mdx) |
| **進行表示** | 進捗の度合いを伝える (10 秒以上 / ステップ系) | ProgressBar, Stepper | [Progress Indicators](./progress-indicators.mdx) |
| **入力検証** | フォーム入力の正誤を伝える | Inline Error, Helper Text | [Inline Validation](./inline-validation.mdx) |

## 使い分けの判断軸

### 1. 時間性 (一時 vs 持続)

```
一時的: Toast (数秒で消える)、Snackbar
持続的: Alert (閉じるまで残る)、Status バッジ
```

短時間で消えるフィードバックは「結果通知」に、画面に残し続けるフィードバックは「状態通知」に使う。

### 2. 場所 (画面端 vs インライン)

```
画面端: Toast (操作と切り離された通知)
インライン: 入力欄直下のエラーメッセージ (操作と密接な関係)
```

「どこで起きたか」を明確に伝えるには、原因となる UI 要素のそばに置く。
一方、コンテキストに依存しない結果通知 (保存完了等) は画面端に集約。

### 3. 対象 (操作結果 vs 状態継続 vs 進捗)

```
操作結果: 「保存しました」「コピーしました」 → Toast
状態継続: 「オフラインです」「メンテナンス中」 → Alert / Banner
進捗: 「3/10 ステップ完了」「45% アップロード済み」 → Progress
```

## 関連コンポーネント

| Composite / Primitive | 用途 |
|---|---|
| `Toast` / `ToastProvider` / `useToast` | 即時通知 (画面端、自動消滅) |
| `Alert` | インライン定常通知 (バナー型、ユーザーが閉じる) |
| `Spinner` / `Skeleton` | 待機状態 |
| `ProgressBar` | 進捗表示 |
| `Input` / `Textarea` (`error` prop) | 入力検証メッセージ |

## チェックリスト

- [ ] すべての操作に何らかのフィードバックがある
- [ ] 1 秒以上待たせる処理に Loading が表示される
- [ ] 一時通知 (Toast) と定常通知 (Alert) を混同していない
- [ ] エラー通知は `role="alert"` または `aria-live="assertive"` を持つ
- [ ] フィードバックの色だけに頼らず、アイコンやテキストでも意味を伝えている
